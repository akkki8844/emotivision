# EmotiVision

A real-time facial-expression recognition research prototype that runs entirely in the browser.

**Human facial expression -> camera -> computer vision -> machine learning -> digital interpretation**

> Everything the app shows is an **AI-estimated facial-expression category**, not a measurement of anyone's true
> internal emotional state. The app never claims to know how you feel; it estimates the most likely *visible*
> expression category and says "Expression uncertain" when it cannot decide.

## What it does

- Live webcam with face box, label, confidence, FPS, inference and pipeline latency, face-detection and model status.
- 8 expression classes from a neural network (angry, contempt, disgusted, fearful, happy, neutral, sad, surprised)
  plus **valence and arousal** (an affect map, with region words such as Excited, Calm, Tense, Relaxed).
- **Extras (rule-based, not the network): Geeked, Wink, Kissy face.** "Geeked" fires for a stuck-out tongue or a very
  lopsided, goofy face. See "Extras" below for exactly how it works and how far to trust it.
- Temporal smoothing, prediction stability, an "uncertain" state, and a live timeline.
- Dashboard: live analysis, distribution, timeline, model information, session statistics.
- Experiment mode: start/stop a session (free or guided protocol), then a report with distribution, confidence
  statistics, timeline, observed changes, agreement with the instructed pose, JSON/CSV/PDF export.
- Model evaluation: metric definitions, test procedure, and an in-browser **Evaluation Lab** that computes accuracy,
  precision, recall, F1, confusion matrix, per-class FP/FN on a labelled image folder you choose.
  Until you run it, every metric reads **"Evaluation required"**. No numbers are invented.
- STEAM-H panel, Bias and limitations panel, Privacy panel.

## Quick start

Requires Node.js 20+ and a modern Chromium-based browser, Firefox or Safari with a webcam.

```bash
npm install
npm start          # = npm run setup + npm run build + vite preview on http://127.0.0.1:4173
```

Open <http://127.0.0.1:4173>, wait for "Model ready", press **Start camera**.

Other commands:

```bash
npm run setup      # copy runtime files from node_modules and download + verify the model (needs internet once)
npm run dev        # development server on http://127.0.0.1:5173 (run npm run setup first)
npm run build      # typecheck + production build to dist/
npm run preview    # serve dist/
npm test           # unit tests (vitest)
npm run typecheck
```

`npm run setup` does three things: copies the MediaPipe Face Mesh runtime to `public/mediapipe/face_mesh`, copies the
ONNX Runtime WASM files to `public/ort`, and downloads the expression model to `public/models/` and verifies its SHA-256.
After that the app needs **no network at all**.

### Model installation

The model is `enet_b0_8_va_mtl.onnx` from EmotiEffLib / HSEmotion:

```
https://github.com/sb-ai-lab/EmotiEffLib/blob/main/models/affectnet_emotions/onnx/enet_b0_8_va_mtl.onnx
SHA-256 c43e056ad388d4a8dc911832b8291435b2af537f967e5870ebd731574ec7e812
```

`npm run setup` downloads it for you. To do it by hand, place the file at `public/models/enet_b0_8_va_mtl.onnx`.
If your network blocks `raw.githubusercontent.com`, download the file on another network and copy it there.

### Hosting notes

The app uses multi-threaded WebAssembly, which needs the page to be cross-origin isolated. `vite preview` and `vite dev`
already send the required headers (`Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`).
If you host `dist/` elsewhere, send the same two headers (without them the app still works, single-threaded and slower),
and serve over HTTPS (browsers only allow the camera on HTTPS or localhost). The production build also ships a
Content-Security-Policy that only allows connections to its own origin.

## The ML pipeline

1. **Camera** (`camera.ts`): `getUserMedia`, front camera, up to 1280x720. Frames stay in a `<video>` element.
2. **Face detection + landmarks** (`faceTracker.ts`): MediaPipe Face Mesh (BlazeFace detector + 468-point landmark
   network) in WebAssembly. One face (the most confident).
3. **Alignment / normalisation** (`alignment.ts`): the line between the eye centres gives head roll. The frame is rotated
   so the eyes are level and a square that covers all landmarks (x1.15 margin) is warped to 224x224. This removes
   position, distance and in-plane tilt.
4. **Quality gate** (`alignment.ts`): face size, brightness, blur and a yaw proxy (nose position between the cheeks).
   Soft problems show a warning on the video; hard problems (face under 64 px, very dark, head turned far) force
   "Expression uncertain" instead of a guess.
5. **Expression model** (`expressionModel.ts`): EfficientNet-B0 -> 8 logits + valence + arousal. Preprocessing: RGB,
   /255, ImageNet mean/std, NCHW float32. Softmax over the 8 logits.
6. **Temporal smoothing** (`temporal.ts`): time-constant EMA on probabilities (350 ms, frame-rate independent),
   hysteresis (a new class must lead by 8 points to replace the shown label), a 1.5 s stability window, and an
   uncertainty decision (smoothed confidence < 50 % or top-two margin < 12 points). Face loss up to 0.5 s is bridged.
7. **Analytics** (`analytics.ts`): time per category, confidence statistics, latency, state transitions.
8. **Visualisation**: canvas overlay with eased box, probability bars, distribution, stacked timeline, affect map.

Frames are processed with two overlapping stages: detection of frame N+1 runs while the model of frame N is running.

## The model, and why it was chosen

| | |
|---|---|
| Model | HSEmotion / EmotiEffLib `enet_b0_8_va_mtl` |
| Architecture | EfficientNet-B0, multi-task head: 8 expression logits + valence + arousal (ONNX, 16 MB) |
| Training data | Pre-trained for face identification on VGGFace2, then trained on AffectNet (over a million web images, about half manually labelled; 8 expression classes plus valence/arousal) |
| Classes | 8: anger, contempt, disgust, fear, happiness, neutral, sadness, surprise |
| Input | 224 x 224 RGB aligned face crop |
| Reported accuracy | 61.93 % on AffectNet 8-class validation, as published by the authors (chance is 12.5 %). **Not measured by this app.** |

Why this one:

- Small enough (16 MB, a few hundred million operations) to run in the browser at interactive rates, so the data never
  has to leave the device.
- Published benchmark numbers and results in the ABAW competitions.
- Next size up (`enet_b2_8`) reports 63.03 % but is about twice the size and about 3x slower on the authors' phone benchmark
  (191 ms vs 59 ms). About one point of accuracy was not worth that for a live demo.
- The multi-task variant adds valence/arousal at no cost and reports slightly higher AffectNet accuracy than the plain 8-class checkpoint (61.93 % vs 61.32 %).
- Code is Apache-2.0. Check the licence of the weights and of the AffectNet data before any commercial use.

Limitations and bias sources: web-scraped, mostly posed and frontal training photos; heavy class imbalance (happy and
neutral dominate); human labels with high annotator disagreement; one cultural reading of expressions; sensitivity to
lighting, camera quality, head angle, occlusion and facial variation. See the in-app "Bias & limits" tab.
A pre-trained model is a component, not a guarantee. This project's contribution is the engineering around it:
alignment, quality gates, smoothing, abstention, analytics, reports and an evaluation tool.

## Extras: Geeked, Wink, Kissy face

These are **not** from the neural network, which only knows the 8 classes. They are rule-based detectors in `core/play.ts`:

- **Geeked**: a tongue-colour cue below the lower lip (how far a reddish run extends downward from the inner lower lip,
  compared with the mouth width and the upper lip, using colour relative to the person's own cheek skin), **or** several
  face asymmetries at once (mouth shifted sideways, tilted mouth corners, one eyebrow much higher, one eye closed). A single
  lopsided feature alone does not trigger it.
- **Wink**: one eye's opening is much smaller than the other's, with the other clearly open, held about 0.26 s (so blinks are ignored).
- **Kissy face**: mouth much narrower than normal and not open.
- Scores are smoothed (fast attack, slow release), need a minimum hold time, and use on/off hysteresis (0.6 / 0.4).
  While one is active it replaces the network's label in the headline and on the video; the network's answer is still shown.
- The Extras panel has a "Show measured features" view, and Pipeline settings has an **Extras sensitivity** slider
  (0 turns them off) so you can calibrate them for your face and camera.

What is and is not verified:

- Verified: unit tests of the scoring and hold/hysteresis logic; no false triggers on 7 posed expression photos
  (angry, disgusted, fearful, happy, neutral, sad, surprised); the tongue-colour cue responds to a synthetic pink tongue painted onto a neutral photo.
- **Not verified:** real tongue-out and real wink photos or video. I could not obtain labelled examples in the build
  environment, and a painted eyelid does not make the face-mesh model see a closed eye. The thresholds are hand-set. Expect
  to adjust the sensitivity slider. Kissy face is the least certain. Treat all three as a fun, experimental layer.
- Crossed-eyes was considered and dropped: it needs iris landmarks, and enabling them made face detection fail on some still photos.

## Testing procedure

```bash
npm run typecheck
npm test            # 27 unit tests: softmax/entropy, temporal smoothing, alignment maths, metrics, labels, extras logic
npm run build
```

Manual end-to-end checks:

1. `npm start`, open the app, confirm "Model ready" and "Camera processing: Local".
2. Start the camera. Confirm the box follows your face, FPS/latency update, and "No face detected" appears when you leave frame.
3. Make clear expressions (smile, frown, open mouth wide). Confirm the label changes smoothly and the timeline fills.
4. Cover half the lens or dim the light: confirm warnings and "Expression uncertain" instead of a confident label.
5. Try tongue out, a wink, a kissy face. Open "Show measured features" and adjust Extras sensitivity if needed.
6. Experiment tab: run a guided session, stop, check the report and downloads.
7. Privacy: open DevTools -> Network while using the app: only same-origin requests. Go offline after loading: it keeps working.

Automated browser test used during development (not part of the repo): headless Chrome with
`--use-fake-device-for-media-stream --use-file-for-fake-video-capture=<clip>.y4m` driving the real UI.

## Model evaluation procedure

The Model evaluation tab explains the metrics and contains the Evaluation Lab.

1. Choose a labelled benchmark (AffectNet validation, FER2013/FER+ test, RAF-DB test, CK+, or your own consented, labelled photos) and note its name and split.
2. Arrange a folder with one sub-folder per expression: `test/happy/*.jpg`, `test/sad/*.jpg`, ... (accepted names: angry/anger, contempt, disgust(ed),
   fear(ful), happy/happiness, neutral, sad/sadness, surprise(d)).
3. In the lab choose the folder, name the dataset, choose "Already-cropped faces" (FER-style crops) or "Full photos" (detect + align first),
   tick "Only allow classes present in the dataset" for 7-class sets, set a per-class cap (seeded, reproducible), and run.
4. Read accuracy, balanced accuracy, macro/weighted F1, per-class precision/recall/F1/support, FP, FN, no-face counts, the confusion matrix,
   mean confidence when right vs wrong, and the most confident errors. Download the JSON.
5. Repeat on slices (lighting, pose, age, skin tone, gender, glasses) to look for bias. Use cross-dataset tests: the model was trained on AffectNet, so AffectNet scores are optimistic.

Smoke test only (not a benchmark): the 7 posed sample photos from the face-api.js repository were all classified as their labelled
expression by the full pipeline. That is 7 images of what look like a few people: it demonstrates the pipeline works, and says nothing about accuracy.

## Measured performance (this build, one machine)

On a 12-thread laptop with an Intel integrated GPU, while a busy desktop browser was also running, the model alone took about 30-85 ms
(WASM, 4 threads) and the full pipeline ran at roughly 6-16 FPS, depending on background load. Face detection took about 14-55 ms.
Your numbers will differ; the app shows them live. WebGPU was tried (`?backend=webgpu`) and was slower on that integrated GPU because the face
landmarker already uses it, so WASM is the default.

## STEAM-H

- **Science**: expressions are muscle configurations (zygomaticus, frontalis, orbicularis oculi...). A camera records light, not muscles; computer vision turns pixels into landmark positions and learned features, then into scores. The step from appearance to feeling is a contested hypothesis.
- **Technology**: webcam -> pixels -> CNN -> 8 scores + valence/arousal, locally with WebAssembly (ONNX Runtime Web, MediaPipe).
- **Engineering**: a staged pipeline (camera, detection, alignment, preprocessing, inference, temporal filtering, analytics, visualisation), each stage testable; trade-offs (smoothing vs reaction speed, threshold vs coverage, model size vs accuracy) are visible and adjustable.
- **Arts**: colour, motion, an overlay tied to the face, a stacked timeline and honest "uncertain" states make invisible predictions understandable.
- **Mathematics**: softmax, EMA `p_t = p_(t-1) + a (x_t - p_(t-1))` with `a = 1 - e^(-dt/tau)`, entropy, percentages, medians/percentiles/standard deviation of time series, precision/recall/F1, confusion matrices.
- **Humanities**: consent, privacy, cultural variation, dataset bias, and the scientific and ethical limits of inferring emotion from appearance (Barrett et al., 2019, *Psychological Science in the Public Interest*; the EU AI Act prohibits emotion inference in workplaces and schools except for narrow medical/safety uses).

## Privacy and ethics

- Camera processing: **Local**. Frames go camera -> video element -> in-memory canvas -> tensor -> numbers. Nothing is uploaded.
- No recording, screenshots, files, cookies, localStorage or IndexedDB. No analytics, no third-party scripts, fonts or CDNs.
- Session statistics live in tab memory and vanish on reload. Reports are saved only if you click Download, and contain only numbers.
- The production CSP only allows connections to the app's own origin, so the browser enforces the no-upload promise.
- The Evaluation Lab reads your image files in memory only.
- Use only on yourself or with clear consent, and never to judge, grade, hire, monitor or discipline anyone.
- The app never says "the AI knows how you feel"; it says "the model estimates the most likely visible facial-expression category".

## Known limitations

- Single face (the most confident one). In group photos, which face is analysed is not controllable.
- Extras are heuristic and not validated on real tongue/wink data (see above).
- The face-crop margin, uncertainty threshold, smoothing and quality-gate values are engineering choices, not calibrated constants. Softmax confidence is not a calibrated probability.
- No dataset benchmark ships with the app; use the Evaluation Lab.
- Tested with Chrome. The face-landmark runtime (the legacy MediaPipe Face Mesh solution) is deprecated by Google but still works, and ships its model files inside the npm package so nothing is fetched from a CDN.
